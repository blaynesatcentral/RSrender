# ArcGIS Pro Layout lifecycle, navigation, export, and accessibility research

Status: evidence record for Wayfinder ticket #6  
Research date: 2026-08-13  
Benchmark: ArcGIS Pro 3.7 documentation, 3.7 SDK surface, and the ArcGIS Pro 3.7 Accessibility Conformance Report; [Esri lists 3.7.1, released 2026-07-07, as the current patch](https://support.esri.com/en-us/knowledge-base/faq-what-are-the-build-numbers-for-releases-of-arcgis-p-000012500)  
Scope: page navigation, page/printer setup, layout property workflows, project lifecycle, undo/redo scope, printing, PDF export, keyboard access, accessibility, defaults, persistence, prompts, errors, and clean-room adoption by RSrender. This study concerns observable behavior and public interfaces only; it does not reproduce Esri code, assets, branding, or trade dress.

## Executive findings

ArcGIS Pro offers a strong command vocabulary for navigating and publishing a page: page-relative pan and zoom, exact layout properties, printer-aware page setup, previewable tiling, nonblocking background export, rich PDF fidelity controls, map-series page selection, tagged PDF, alternative text, and explicit reading order. These are useful capability benchmarks. They should not be copied as one undifferentiated workflow.

ArcGIS Pro's lifecycle is project-centric. One `.aprx` contains layouts as well as maps, connections, and saved open/active views; one project is current per application instance; a project-level dirty flag and save prompt protect that aggregate. RSrender's units are different: a **Log Template** is reusable layout behavior, a **Log Project** owns assignments, Presentation Overrides, and a retained Source Snapshot, and a **Log Document** is an immutable publication. RSrender therefore needs the commercial New/Open/Save/Save As/Close experience without inheriting ArcGIS's broad project boundary or treating workspace-only view changes as document edits.

ArcGIS Pro's recovery model is a useful baseline but not a sufficient destination. It defaults to a five-minute project backup, keeps one overwritten backup in a `.backups` folder, prompts only when that backup is newer, and deletes or abandons one side according to the response. RSrender has already chosen explicit recover/discard/compare behavior and should use atomic, versioned recovery snapshots rather than a single opaque overwrite.

Export is unusually mature. ArcGIS Pro distinguishes layout export from printing, exports in the background by default, can complete with warnings, and exposes PDF raster/vector, font, layer, color, security, and accessibility settings. RSrender should adopt deliberate destination selection, nonblocking work, font and color diagnostics, and accessible PDF metadata. It should intentionally diverge by running its **Diagnostic** gate before publication: errors block export; warnings require acknowledgement or a recorded narrow suppression. Post-export warnings alone are too late for a professional boring-log publication workflow.

ArcGIS Pro 3.7's own accessibility report is also a warning against treating the benchmark as a conformance target. Esri reports partial support for keyboard operation, dragging alternatives, focus order, descriptive labels, input-error association, accessible names/roles/states, status announcements, color use, and contrast. RSrender should benchmark the breadth of commands, not reproduce those limitations. Direct manipulation must have exact-property and keyboard equivalents, focus must survive pane/dialog transitions, and every status/diagnostic/export result must be programmatically announced.

## Method and evidence levels

- **D - documented behavior:** stated in current first-party Esri help or a versioned Esri conformance report.
- **S - exposed surface:** named in the ArcGIS Pro 3.7 SDK UI/API reference. This establishes a command or state boundary, but not undocumented pointer geometry or prompt wording.
- **I - inference:** a bounded design conclusion from documented facts. It is not represented as observed ArcGIS behavior.
- **O - observation required:** official sources reviewed do not resolve the behavior. A clean-room session with a licensed current build is required, recording build, operating system, display scaling, input method, steps, result, and permitted screenshots/video.

A licensed ArcGIS Pro executable was not available in this workspace. Accordingly, this pass uses only current first-party Esri documentation, the public SDK surface, and Esri's versioned accessibility report. It does not guess at undocumented pointer actions, transient cues, exact dialog copy, default numeric export values, or save-prompt button order.

## Documented and inferred state model

The following model prevents ArcGIS terminology from silently deciding RSrender behavior:

```text
ArcGIS Pro (documented)                    RSrender adaptation

Application instance                      Electron application/window
  -> one current Project (.aprx)           -> zero or more open document tabs
      -> project IsDirty                       -> Log Template OR Log Project dirty state
      -> layouts, maps, connections            -> type-owned domain content only
      -> open/active views                     -> separate workspace/session state
      -> one overwritten recovery backup       -> bounded integrity-checked Recovery Candidates

Layout export                             Publication command
  -> active layout                         -> resolved Log Set/page selection
  -> background by default                 -> immutable render-plan job
  -> may finish with warnings              -> preflight Diagnostic gate
  -> PDF/file                              -> immutable Log Document (+ optional Publication Audit)
```

Documented ArcGIS states include current project, project dirty/read-only state, active view/layout, selected element(s), activated map frame, current navigation extent/history, export run mode, and newer-backup availability. The exact transition guards between all of these are not fully documented. RSrender should model at least:

- document type and identity;
- clean, dirty, saving, save-failed, read-only, externally-modified, closing;
- recovery absent, available, comparing, recovered-unsaved, discarded;
- source offline/available, Source Snapshot retained, refresh checking, comparison ready, accepted/rejected;
- diagnostics evaluating, errors present, warnings unacknowledged, warnings acknowledged/suppressed;
- export idle, snapshotting, queued, rendering, writing, completed, completed-with-runtime-warning, canceled, failed;
- workspace focus surface, active page/Template Variant, viewport history, canvas/component-edit mode.

## RSrender decisions and consequences

### Adopt

- A complete, shortcut-accessible navigation command set: fit page, page width, 100%, zoom to selection, previous/next extent, pan, and explicit zoom percentage.
- Exact element property editing synchronized with canvas and Contents selection.
- Standard and custom physical page sizes, explicit orientation, printer margin preview, and full print preview.
- User-selected output location and one multipage PDF or deliberate page/exploration subsets.
- Background publication work with visible progress, cancellation, result actions, and an immutable captured input state.
- PDF font/color/rasterization preflight, metadata, semantic reading order, alt text, and tagged accessible output.
- New/Open/Save/Save As/Close, recent files, read-only state, dirty prompts, autosave/recovery, and versioned file behavior expected of commercial desktop software.

### Adapt or improve

- Keep Log Template/Log Project content state separate from workspace zoom, pane, tab, and selection state even though ArcGIS saves open/active views in the project.
- Replace one-project-per-process lifecycle with per-tab document identity and a deliberate multi-document close review.
- Replace ArcGIS's one overwritten backup and destructive recovery choice with bounded integrity-checked Recovery Candidates and deliberate review paths; exact review commands remain a #35 decision.
- Replace post-export warning discovery with the settled Diagnostic gate and an optional Publication Audit.
- Treat fit-to-paper as a scale-changing exceptional action; show the actual scale and protect the Reference Depth Range/depth scale from silent transformation.
- Store PDF semantic reading order and alternative-text intent in the Log Template instead of repairing them per export.
- Make every direct canvas action operable from Contents, Properties, or a named keyboard command, addressing the gaps in Esri's 3.7 ACR.

### Do not adopt initially

- Map-frame-specific navigation and map-series GIS concepts.
- `.prn` output, advanced PDF permissions/passwords, non-visible PDF layers, attribute-bearing PDF layers, overprint simulation, and a broad gallery of non-PDF export formats.
- Generic auto-scale-on-page-resize behavior that can leave text wrapping, symbols, or spacing inconsistent.
- Any default-on telemetry merely because ArcGIS enables usage/error participation by default.

## Evidence-backed requirements handed to later specification tickets

1. Every content mutation belongs to exactly one open Log Template or Log Project, produces a named undo operation, updates that document's dirty state, and is independent of workspace navigation state.
2. Save uses a failure-safe write/replace protocol; failed saves retain dirty and recovery state. Save As reports exactly which embedded and external dependencies travel with the new file.
3. Autosave/recovery is enabled by default, captures document-owned state without credentials, keeps a bounded sequence, and never destroys the original or recovery candidate before the user resolves it.
4. Opening, closing, replacing, or quitting never discards a dirty document without a named-document Save/Don't Save/Cancel decision. Multi-document quit makes partial save failures recoverable.
5. Background export captures one immutable render plan. Edits after capture affect the document, not the active job.
6. The export gate runs Diagnostics against the resolved Log Set, fonts, overflow/pagination, page geometry, hidden/missing bindings, source freshness, Presentation Overrides, accessibility metadata, and chosen PDF settings. Errors block; warnings require acknowledgement or a narrowly recorded suppression.
7. The PDF destination is user-selected. Output reports page dimensions/count, path, font substitutions/embedding, rasterization, tags, metadata, completion status, and any runtime failure without silently changing settings.
8. Actual physical size is the print default. Any printer-fit transformation displays the scale factor and warns that professional depth/measurement interpretation can change.
9. Canvas navigation, document selection, component-edit mode, and property focus are distinguishable visually and programmatically. Workspace navigation never changes printed geometry.
10. Every essential pointer drag has an accessible command/property alternative; focus restores after transient UI; error/status changes are announced; no state relies on color alone.

## Remaining evidence limits

This ticket does not establish exact ArcGIS pointer behavior, UI geometry, prompt copy, export-option defaults not expressly documented, focus behavior for each Layout control, or failure semantics under damaged/remote filesystems. It also does not claim that Esri's product-wide accessibility findings occur in every Layout workflow. Those are deliberately assigned to the clean-room observation/prototype backlog.

No ArcGIS behavior decides RSrender's source refresh, domain pagination, Source Snapshot, Example Dataset, Presentation Override, Diagnostic, or Publication Audit semantics. Those remain RSrender domain decisions; ArcGIS evidence is used only to decompose interaction and lifecycle capabilities.
