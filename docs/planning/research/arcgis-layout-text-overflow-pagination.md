# ArcGIS Pro Layout text measurement, overflow, and pagination

Status: research evidence for Wayfinder ticket #5  
Researched: 2026-08-13  
Benchmark: ArcGIS Pro 3.6 public help and API documentation; ArcGIS Pro 3.7 accessibility conformance report where noted  
Method: clean-room study of public first-party Esri documentation, tutorials, API references, and published accessibility evidence. No Esri code, project-file reverse engineering, proprietary assets, branding, or trade dress were used.

## Executive findings

ArcGIS Pro has a real, queryable distinction between a text element's frame and whether its rendered text fits that frame. Rectangle text wraps automatically and supports four explicit fitting strategies: do nothing and hide the excess, shrink to a configured minimum, grow the width, or grow the height. When content still does not fit, ArcGIS Pro shows an overflow symbol; its public `TextElement.isOverflowing` property describes that state as typically a red ellipsis. [Edit text](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/text.htm) and the [ArcPy `TextElement` reference](https://pro.arcgis.com/en/pro-app/3.6/arcpy/mapping/textelement-class.htm) are the controlling evidence.

That is a useful interaction benchmark but not a sufficient RSrender policy. ArcGIS Pro's default intentionally leaves excess text undisplayed. Its grow-width and grow-height strategies may move content off the page, and its shrink strategy guarantees only a minimum size, not semantic legibility. No surveyed first-party Layout source documents a document-wide overflow report, an export-blocking fit check, auditable warning suppression, or linked text frames that continue excess text onto another physical page. ArcGIS map series generate data-driven page states from one shared layout; they are not documented as overflow-driven text pagination. Esri itself warns that dynamic text length can vary per map-series page and recommends rectangle text with a fitting strategy to avoid cutoff. See [Spatial map series and dynamic elements](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/use-dynamic-text-with-map-series.htm) and [Create a spatial map series](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/create-a-map-series.htm).

ArcGIS Pro exposes several variables that materially affect measurement: font family and style, variable-font axes, point size, glyph fallback, alignment, word and character spacing, character width, kerning, ligatures, line spacing, margins, columns, rotation, and the text geometry. It also exposes element bounds and fit state to its public APIs. The surveyed sources do **not** publish the exact shaping engine, line-breaking algorithm, glyph-fallback order, fit tolerance, or whether painted effects such as halos participate in the fit calculation. Consequently, RSrender must specify its own deterministic measurement contract and use the same engine and inputs for the live canvas, diagnostics, pagination, and PDF.

## Evidence labels and limits

- **Documented** means a first-party Esri help or API page states the behavior directly.
- **Demonstrated** means an official tutorial, example, screenshot, or API sample exposes the behavior in a reproducible workflow.
- **Inferred** means the conclusion follows from multiple documented facts but is not itself an Esri product contract. Inferences are separated below.
- “Not documented” means not found in the first-party sources surveyed for this ticket. It is not proof that an undocumented behavior cannot exist.
- No licensed ArcGIS Pro session was available. Exact pixels, focus announcements, export treatment of editing adorners, Unicode line-breaking cases, and failure UI for broken dynamic tags remain direct-observation work.

## Atomic behavior matrix

### Measurement, frame geometry, and anchors

| ID | ArcGIS Pro atomic behavior | Evidence and status | Boundary or edge behavior | RSrender treatment |
|---|---|---|---|---|
| TM-01 | Text has both a content string and element geometry. | **Documented.** The [ArcPy `TextElement` reference](https://pro.arcgis.com/en/pro-app/3.6/arcpy/mapping/textelement-class.htm) exposes `text`, `elementWidth`, `elementHeight`, position, rotation, and text size. | Text inside legends, table frames, and other map surrounds is explicitly outside `TextElement`; those containers have separate APIs. | **Adopt concept.** Keep Text Element content, frame geometry, and container-owned text as distinct domain concepts. |
| TM-02 | Width and height are reported in layout page units, while text size is in points. | **Documented.** [`TextElement`](https://pro.arcgis.com/en/pro-app/3.6/arcpy/mapping/textelement-class.htm) defines element dimensions in page units and `textSize` in points. | Mixed units require a deterministic conversion at the current physical page scale. | **Adopt.** Canonical physical units plus an explicit 72-points-per-inch conversion; do not infer from screen pixels. |
| TM-03 | A point-sized character need not visually occupy the full point-size cell. | **Documented.** [Text symbols](https://pro.arcgis.com/en/pro-app/3.6/help/mapping/layer-properties/text-symbols.htm) distinguishes the character cell from actual glyph height and notes that visible height varies by font. | Equal point sizes across font families do not imply equal apparent height or equal fit. | **Adopt as test requirement.** Measure shaped glyph runs, not nominal point size alone. |
| TM-04 | The documented physical conversion is 72 points per inch. | **Documented.** [Text symbols](https://pro.arcgis.com/en/pro-app/3.6/help/mapping/layer-properties/text-symbols.htm) provides the point-to-inch table. | Esri documents whole and half-point entry, but this does not establish an internal precision limit. | **Adopt conversion, improve input.** Permit validated decimal sizes without imposing an arbitrary half-point product limit. |
| TM-05 | Text element position is the position of its selected anchor, not necessarily its top-left corner. | **Documented.** [`TextElement`](https://pro.arcgis.com/en/pro-app/3.6/arcpy/mapping/textelement-class.htm) defines X and Y against the element anchor. | A numerically unchanged position can produce different bounds after an anchor change. | **Adopt.** Persist explicit Position Anchor and derive bounds; never reinterpret stored X/Y silently. |
| TM-06 | Nine anchors are available: four corners, four edge midpoints, and center. | **Documented.** [`TextElement`](https://pro.arcgis.com/en/pro-app/3.6/arcpy/mapping/textelement-class.htm) enumerates all nine. | Anchor controls expansion around changing dynamic text. | **Adopt.** All auto-grow and dynamic reflow must state the fixed anchor and resulting growth direction. |
| TM-07 | Anchors are intended to control how an element expands when its text changes. | **Documented.** The [`setAnchor` discussion](https://pro.arcgis.com/en/pro-app/3.6/arcpy/mapping/textelement-class.htm) uses center-anchored dynamic title text as the example. | Center anchoring expands in more than one direction and can create two-sided collisions. | **Adopt with diagnostics.** Recompute page-bound and collision diagnostics after every bound-value change. |
| TM-08 | Rectangle rotation and text rotation are separable; point-text values remain synchronized. | **Documented.** The [`TextElement` discussion](https://pro.arcgis.com/en/pro-app/3.6/arcpy/mapping/textelement-class.htm) distinguishes `elementRotation` from `textAngle`. | Fit can depend on unrotated frame coordinates while painted page bounds depend on rotation; the exact Esri test is not published. | **Adapt.** Define fit in local frame coordinates and page collision in transformed coordinates. |
| TM-09 | The public API exposes a boolean fit result for text geometry. | **Documented.** [`TextElement.isOverflowing`](https://pro.arcgis.com/en/pro-app/3.6/arcpy/mapping/textelement-class.htm) is true when text does not fit the supplied geometry. | It is a boolean, not a documented overflow amount, cutoff line, or reason code. | **Improve.** Diagnostics need measured required bounds, available bounds, affected text range, policy, and severity. |
| TM-10 | Public SDK element APIs expose element bounds and a frame-fit query. | **Documented API evidence.** The [ArcGIS Pro SDK `TextElement`](https://pro.arcgis.com/en/pro-app/latest/sdk/api-reference/topic11172.html) and base [Element](https://pro.arcgis.com/en/pro-app/latest/sdk/api-reference/topic11058.html) expose bounds and `DoesFitFrame`. | Public documentation does not specify shaping library, tolerance, or which painted effects count toward fit. | **Adopt outputs, specify algorithm.** RSrender must make inputs and tolerance part of the rendering contract. |
| TM-11 | Horizontal alignment controls which side of text remains fixed as text expands. | **Documented.** [Text symbols](https://pro.arcgis.com/en/pro-app/3.6/help/mapping/layer-properties/text-symbols.htm) explains left, center, and right expansion behavior. | Text alignment and element Position Anchor are independent controls that can interact. | **Adopt, expose separately.** Label alignment as content alignment and anchor as frame positioning. |
| TM-12 | Paragraph metrics can include margins, word spacing, character spacing, character width, line spacing, ligatures, kerning, glyph hinting, language/region, and block progression. | **Documented.** [Text symbol properties](https://pro.arcgis.com/en/pro-app/latest/help/mapping/layer-properties/text-symbol-properties.htm) enumerates these properties. | Any one can change line breaks or bounds; exact defaults and fallback behavior must be serialized for reproducibility. | **Adapt.** Support the subset the product exposes, but every supported metric must enter the single measurement cache key. |

| TT-10 | Inline editing supports selection-scoped font changes and bulleted lists. | **Documented.** [Edit text](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/text.htm) describes selection formatting during inline edit. | An element can therefore contain mixed formatting that changes measurement within a paragraph. | **Adopt bounded rich text.** Persist paragraph/span runs and measure the exact run sequence. |

### Fitting policies and visible overflow

| ID | ArcGIS Pro atomic behavior | Evidence and status | Boundary or edge behavior | RSrender treatment |
|---|---|---|---|---|
| OF-01 | Rectangle text has exactly four documented fitting strategies. | **Documented.** [Edit text](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/text.htm) lists None, Adjust Font Size, Adjust Width, and Adjust Height. | Strategies are unavailable for other text types. | **Adapt vocabulary.** Expose policy by element and never infer it from element type alone. |
| OF-02 | `None` is the default strategy. | **Documented.** [Edit text](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/text.htm). | Default excess content is not displayed. | **Reject as silent-style default.** New bound text should default to wrap plus warning; clipping must be deliberate. |
| OF-03 | With `None`, text outside the box is not drawn and an overflow symbol appears. | **Documented.** [Edit text](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/text.htm). | The source does not state whether the symbol is editing chrome or exported content. | **Adapt.** Clip only by explicit policy, always pair it with a semantic Diagnostic and preview marker. |
| OF-04 | The overflow state is typically displayed as a red ellipsis on the layout. | **Documented API description.** [`TextElement.isOverflowing`](https://pro.arcgis.com/en/pro-app/3.6/arcpy/mapping/textelement-class.htm). | “Typically” leaves type/state exceptions; exact color, placement, zoom behavior, and assistive semantics are unspecified. | **Improve.** Use redundant icon, outline/state, text message, and tree/property badges; never rely on red alone. |
| OF-05 | `Adjust Font Size` only shrinks; it never grows text beyond its authored size. | **Documented.** [Edit text](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/text.htm). | Shorter content does not become larger than the design size. | **Adopt upper bound.** Record authored size separately from computed size. |
| OF-06 | `Adjust Font Size` stops at a configured minimum font size. | **Documented.** [Edit text](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/text.htm). | Content may still not fit at the minimum. The page does not state a global accessibility-safe minimum. | **Adopt with explicit failure.** Minimum is policy input; remaining overflow becomes an error or warning, never further shrinkage. |
| OF-07 | `Adjust Width` changes frame width while preserving height and font size. | **Documented.** [Edit text](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/text.htm). | The resulting text may draw off the page. | **Adapt.** Grow-container must honor anchor, maximum bounds, neighboring constraints, and emit collision/page-bound diagnostics. |
| OF-08 | `Adjust Height` changes frame height while preserving width and font size. | **Documented.** [Edit text](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/text.htm). | The resulting text may draw off the page. | **Adopt selectively.** Useful for headers/notes; not acceptable when it silently changes a fixed depth-aligned Log Column. |
| OF-09 | Area text can remain overflowing even when programmatically inspected. | **Demonstrated.** [`TextElement` examples 5 and 6](https://pro.arcgis.com/en/pro-app/3.6/arcpy/mapping/textelement-class.htm) loop on `isOverflowing` and change font size until fit. | The sample has no minimum or lower-bound guard; copied literally it can violate legibility or fail to terminate on pathological content. | **Reject sample as product policy.** Implement a bounded solver returning success or a typed failure. |
| OF-10 | Legend frames have fitting strategies and can expose an overflow symbol when content does not fit. | **Documented.** [Legend fitting strategies](https://pro.arcgis.com/en/pro-app/latest/help/layouts/layout-fitting-strategies.htm). | Once a minimum is reached, entire legend items may be omitted; later smaller items are not backfilled. | **Reject omission semantics for log data.** Never drop strata, samples, or results to make a page appear complete. |
| OF-11 | Table frames similarly drop an entire field if it does not fit and show an overflow icon. | **Documented.** [Add and modify table frames](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/add-and-modify-table-frames.htm). | A partially fitting field and all later fields can be excluded. | **Reject for required evidence.** Structural data omission must be a blocking export error, not a fitting strategy. |
| OF-12 | Legend wrapping can be configured at a width measured in page units. | **Documented.** [Format text in a legend](https://pro.arcgis.com/en/pro-app/latest/help/layouts/text-in-a-legend.htm). | The setting propagates to title, headings, labels, and descriptions. | **Adapt.** Shared styles may provide defaults, but per-element overrides and resulting diagnostics remain explicit. |
| OF-13 | A page resize can proportionally scale text and element geometry, but wrapping and customized text spacing are not automatically recalculated as equivalent authored settings. | **Documented.** [Change a layout](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/change-layout.htm). | Esri warns resized results may look different and require manual correction. | **Improve.** Changing page size must be an explicit transform with full deterministic repagination and a before/after diagnostic review. |
| OF-14 | No surveyed export page documents an overflow preflight or export block. | **Document-survey result.** [Export to PDF](https://pro.arcgis.com/en/pro-app/3.6/help/sharing/overview/pdf-export.htm) enumerates export properties without a text-fit gate; [Edit text](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/text.htm) describes the local symbol only. | Absence from these pages is not proof no other UI warning exists. It is an observation gap. | **Depart deliberately.** RSrender errors block export; warnings require acknowledgement; suppressions stay counted and auditable. |

### Fonts, rendering, PDF, and accessibility

| ID | ArcGIS Pro atomic behavior | Evidence and status | Boundary or edge behavior | RSrender treatment |

## Documented facts versus product inferences

The matrix above keeps first-party statements atomic. The following conclusions are useful for RSrender but are **inferences**, not claimed ArcGIS contracts:

1. **Frame bounds and painted bounds are likely different concepts.** Esri exposes geometry, rotation, text angle, halos/callouts, and a fit boolean, but does not publish whether shadows, halos, or callout strokes participate in fit. RSrender should therefore calculate content fit, painted bounds, page bounds, and collision bounds separately. Sources: [Text symbols](https://pro.arcgis.com/en/pro-app/3.6/help/mapping/layer-properties/text-symbols.htm), [`TextElement`](https://pro.arcgis.com/en/pro-app/3.6/arcpy/mapping/textelement-class.htm).
2. **Fit must be reevaluated per resolved dataset and page.** Esri warns dynamic strings vary by page and can be cut off; a representative-page check is therefore inadequate. Source: [Spatial map series and dynamic elements](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/use-dynamic-text-with-map-series.htm).
3. **A red ellipsis is local feedback, not demonstrated preflight.** The editing and API pages define the local state, while the export page does not document global aggregation or gating. Sources: [Edit text](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/text.htm), [Export to PDF](https://pro.arcgis.com/en/pro-app/3.6/help/sharing/overview/pdf-export.htm).
4. **ArcGIS map series are not a model for flowing a long boring-log narrative.** Their page identities come from index features/bookmarks and their layout is shared. Text continuation would require additional ownership and source-range semantics. Sources: [Create a spatial map series](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/create-a-map-series.htm), [Create a bookmark map series](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/create-a-bookmark-map-series.htm).
5. **Machine-dependent font availability can change pagination.** Esri loads local/temporarily registered fonts and falls back for absent glyphs; without a pinned font/fallback contract, line breaks are not portable. Source: [Text symbols](https://pro.arcgis.com/en/pro-app/3.6/help/mapping/layer-properties/text-symbols.htm).
6. **Grow-to-fit can cause a second-order layout failure.** Esri explicitly warns width/height growth may draw off-page. A successful text fit is therefore not a successful page. Source: [Edit text](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/text.htm).

## Specification-ready requirements derived from the evidence

These are RSrender requirements, not claims about ArcGIS Pro:

1. A Text Element stores authored content/runs, binding runs, frame geometry, Position Anchor, content alignment, text metrics, overflow policy, minimum/maximum constraints, and stable identity independently.
2. Measurement returns at least shaped runs, line boxes, required local bounds, painted transformed bounds, fit status, clipped source range, effective font size, fallback substitutions, and deterministic error codes.
3. The same versioned shaping, line-breaking, measurement, and PDF-placement implementation drives live canvas, page planning, Diagnostics, and export.
4. Every bound value is evaluated against all generated page contexts before export. The active page is never treated as proof that the Log Document fits.
5. Overflow resolution order is explicit and serializable. A policy may compose controlled steps—for example wrap, then shrink no lower than 7.5 pt, then warn—but cannot silently introduce another step.
6. `grow-container` succeeds only if the resulting transformed bounds remain within allowed page/container bounds and satisfy collision/constraint rules. The Position Anchor determines growth direction.
7. `continue/paginate` is permitted only for semantically continuable content. It records consumed source ranges so text is neither lost nor duplicated and produces stable continuation markers/page ownership.
8. Fixed-depth semantic tracks never solve text pressure by omitting Source Data or altering depth correspondence. They emit a blocking Diagnostic or invoke a specifically authored continuation/annotation strategy.
9. Empty, null, unavailable, unauthorized, parse-error, and invalid-type results remain distinct. Display fallback and diagnostic severity are authored per binding.
10. Font substitution, missing glyphs, unavailable font styles, and prohibited PDF embedding are explicit preflight results. Fallback is deterministic and affects measurement before page planning.
11. Diagnostics are reachable from the canvas, Contents tree, Properties pane, and a centralized keyboard-accessible list. Each diagnostic can focus the exact page/element and explain the current policy.
12. Export operates on the exact preflighted Page Plan. It cannot silently remeasure, substitute, repaginate, clip, or omit content without invalidating that preflight and presenting the new result.

## Unverified clean-room observation backlog

1. Does the red overflow ellipsis appear in exported PDF/print, or is it layout-view editing chrome only?
2. Where exactly is the symbol placed for unrotated and rotated rectangle, polygon, circle, and ellipse text, and at which zoom levels is it visible?
3. Is overflow state exposed in Contents, the Element pane, tooltips, status UI, or only on-canvas and through APIs?
4. Is the overflow state announced by JAWS/NVDA, and can a keyboard-only user navigate directly to it?
5. What is the exact fit tolerance at fractional page units and sub-point text sizes?
6. Does fit include paragraph margins, borders, background insets, halos, shadows, callout leaders, underline, and glyph overhangs, or only text layout bounds?
7. How do rotations, negative angles, vertical/block progression, superscript/subscript, and mixed-size runs affect `isOverflowing`?
8. What line-break algorithm applies to long unspaced tokens, soft hyphens, nonbreaking spaces, tabs, CJK, right-to-left text, combining marks, emoji, and missing glyphs?
9. Does ArcGIS hyphenate by language, and if so how is language selected for a text element?
10. What is the actual glyph-fallback order, and does a fallback change trigger an on-screen warning or only a changed rendering?
11. What UI appears when a saved font family or named variable-font instance is unavailable on reopen?

14. Does tagged PDF include clipped-but-undrawn text in its content or structure tree? Does it preserve the visual column reading order?
15. Does export recalculate dynamic text/fit independently, and can the result differ from the visible page without a refresh?

17. Verify directly that there is no supported linked-text-frame or overflow-to-next-layout/page workflow in ArcGIS Pro 3.6/3.7.
18. When Adjust Width/Height causes page-bound escape or overlap, does ArcGIS emit any second diagnostic beyond text fit success?
19. When font-size adjustment reaches its minimum and still fails, does the same overflow marker remain and is the computed size persisted or recomputed?
20. Do screen readers receive the full source string or only the visibly drawn portion when a Text Element is clipped?

## Research disposition

This ticket is research-complete for the public first-party evidence pass. The observation backlog remains prerequisite evidence for pixel-level emulation claims, but it does not block specifying RSrender: the application must intentionally go beyond the benchmark with deterministic measurement, typed missing-data states, explicit per-element policies, cross-page continuation rules, aggregate Diagnostics, export gating, accessible discovery, and font-portability preflight.
