# ArcGIS Pro table interaction and Microsoft Word page-layout research for an RSrender authoring beta

Status: evidence record and beta disposition  
Research date: 2026-08-24  
Benchmarks: current first-party ArcGIS Pro documentation and Microsoft Word for Microsoft 365/Word 2024 documentation  
Scope: row and column navigation, synchronized record inspection, presentation-value editing, validation, filtering, sorting, bounded bulk operations, performance expectations, history, page geometry, margins, gutter, Header/Footer behavior, pagination, Template Variants, rulers, guides, and printer-safe diagnostics. This study concerns observable behavior and public documentation only; it does not reproduce Esri or Microsoft code, assets, branding, or trade dress.

## Executive findings

ArcGIS Pro establishes a strong interaction model for dense records. Keyboard focus, the active row, the selection set, and a highlighted subset are distinct states. The table can show only selected records, and selection is dynamic across a chart, map, and attribute table. A chart hover reveals the variables and exact values for its associated record or records. For RSrender, this supports one stable record/field identity shared by the Data Track, record table, and Properties inspector. It does **not** support creating or synchronizing a second editable chart-data model.

ArcGIS also establishes productive table mechanics: arrow/Tab/Enter navigation, `F2` editing, Enter-to-commit, Escape-to-cancel, Go To Row, Find, selected-row calculation scope, read-only field affordances, domain validation, visible filter state, single- and multi-field sorting, and undo/redo before the final data commit. RSrender should adopt the mechanics but intentionally change the authority boundary. **Source Data remains read-only.** An editable cell can create or update only a project-owned Presentation Override or another explicitly project-owned presentation field, with the original source value and provenance always inspectable.

Microsoft Word establishes explicit physical-page state: paper size, orientation, margins, gutter, Header/Footer distances, page breaks, section-scoped formatting, rulers, nonprinting grids, and snap-to-grid/object behavior. It also shows why document geometry and printer capability must remain separate: minimum printable margins depend on the printer, and content can be truncated when section margins enter the nonprinting region. RSrender should keep portable Log Template geometry authoritative and treat the current printer's nonprinting region as an ephemeral overlay and Diagnostic input.

The efficient beta should deliver the common authoring loop: inspect a large read-only record set, select a record in any view, see the exact plotted values in the table/Properties inspector, create a visibly marked Presentation Override when permitted, navigate and filter without losing identity, undo/redo the operation through shared project history, and edit a deterministic physical page with Header/Depth Body/Footer regions, rulers, guides, snapping, and printer-safe warnings. Arbitrary field scripts, source schema edits, joins, facing-page/book-fold publishing, and Word-like free-form section systems are later scope.

## Method and evidence levels

- **D - documented behavior:** stated in current first-party Esri or Microsoft documentation.
- **I - inference:** a bounded RSrender design conclusion from documented facts and the repository's domain boundary; it is not represented as product behavior in ArcGIS Pro or Word.
- **O - official evidence gap:** the reviewed first-party sources do not establish the behavior. RSrender must specify and test it independently.

Only official Esri and Microsoft sources were used. The products were not installed or behaviorally observed in this workspace. In particular, the reviewed ArcGIS documentation does not disclose its table virtualization implementation or a numeric UI performance envelope, and the reviewed Word documentation does not establish Publisher-style draggable ruler guides or a universal printable-safe inset.

## Non-negotiable RSrender authority boundary

The root [ubiquitous language](../../../CONTEXT.md) defines Source Data as read-only and a Display Value Override as a project-local presentation replacement that retains original Source Data for comparison. The table must therefore expose three different kinds of cells:

1. **Source-original cell:** inspect, select, copy, filter, sort, and find; never directly edit.
2. **Presentation cell eligible for override:** edit creates or changes a Presentation Override; display the override marker and keep the source-original value/provenance one action away.
3. **Project-owned presentation field:** directly editable when its contract allows it; it is never labeled or persisted as Source Data.

This is an intentional departure from ArcGIS Pro. ArcGIS documents both read-only data sources and editable attribute tables, but RSrender must not reproduce the database-edit and Save Edits boundary. The shared Application Core owns one project command/history transaction; the Render Dataset and page scene remain derived projections. See the [domain contract](../specifications/boring-log-domain-model.md), [Source Snapshot acceptance ADR](../../adr/0005-source-snapshot-acceptance-boundary.md), and [main-owned Application Core ADR](../../adr/0008-main-owned-application-core-and-least-capable-electron-topology.md).

| SYNC-05 | **I:** ArcGIS's cross-view behavior establishes shared identity and selection, not a requirement for duplicated data.                                                                                                                                                                     | **Contract rule.** A plotted mark retains the exact Render Dataset/source projection identity needed to locate its table row and Inspector values. Tooltip and Inspector format the same immutable fact plus current Presentation Override; neither reparses rendered pixels nor authors another record. |

Recommended beta state model:

```text
hoveredRecordId       transient; pointer only; no dirty/history effect
activeCell            keyboard focus; exactly zero or one
activeRecordId        inspection target; can differ from selection
selectedRecordIds     ordered/set selection shared across views
editDraft             uncommitted project-owned presentation value
```

Selection changes update all subscribing views. Hover may temporarily emphasize the same identity elsewhere but must not change the selection. If an edit draft is invalid or uncommitted, changing the active record invokes the explicit commit/cancel policy rather than silently losing it.

### Performance and virtualization

ArcGIS calls out Go To Row as useful for tables with many records and offers selected-only display, filtering, hidden/frozen columns, and direct navigation. Those are observable interaction benchmarks, but the reviewed official sources do **not** document ArcGIS Pro's row virtualization algorithm, cache size, overscan policy, scroll anchoring, maximum supported row count, or latency thresholds. No claim of ArcGIS virtualization parity is justified.

RSrender must set its own beta performance contract:

- Virtualize row rendering and column cells so DOM cost tracks the viewport, not total records.
- Keep selection and active-record identity independent of mounted rows.
- Preserve focused/selected row visibility through sort, filter, and override commits when that identity remains in the result; otherwise explain that the active filter hides it.
- Perform filter/sort indexes over the immutable table projection or a bounded worker result, never over rendered cell text.
- Keep tooltip/Inspector lookup identity-based and constant-time with respect to visible row count.
- Test at a declared representative and worst-supported corpus with acceptance budgets for initial open, keyboard move, scroll, filter, sort, selection synchronization, and override commit.
- Announce loading or incomplete result state; never render a partial row set as though it were complete.

## Recommended beta contract

### Must-have table and synchronized inspection behavior

1. One virtualized, renderer-neutral record projection over the current Render Dataset, with explicit source-original, displayed, and project-owned presentation columns.
2. Arrow/Tab/Shift+Tab/Enter/Home/End navigation, `F2` edit for eligible presentation cells, Enter commit, Escape cancel, Ctrl+F Find, and Go To Row/identity.
3. Distinct hover, active cell/record, and selection state. Selection synchronizes across table, canvas/Data Track, and Properties inspector by stable identity.
4. Canvas hover shows exact record/series values. Selection opens the same record in the table/Inspector without copying it into a second data model.
5. Visible sort/filter state, selected-only view, deterministic multi-field sorting, Find/Select Matches, and Clear commands. These are workspace state and do not dirty a Log Project.
6. Presentation Override edits show source original and provenance, validate before commit, and enter shared Log Project undo/redo as one command.
7. Bulk Set/Replace is limited to eligible project-owned presentation targets, previews exact scope and eligible/skipped/error counts, and commits as one undoable transaction.
8. Declared large-corpus budgets and tests for open, scroll, navigation, filter, sort, cross-view selection, tooltip lookup, and override commit.

### Must-have physical-page behavior

1. Always-visible physical page size, orientation, units, margins, active Template Variant, and Header/Depth Body/Footer geometry.
2. Direct manipulation and exact numeric editing for Page Region bounds, with one shared history path and deterministic repagination.
3. First/continuation/last Template Variant behavior instead of a generic Word section tree.
4. Horizontal/vertical rulers, nonprinting grid/guides, snap-to-grid/guide/object feedback, and a temporary snap bypass.
5. Preview based on the same renderer-neutral resolved geometry used for publication.
6. Printer-dependent safe-region overlay and Diagnostic when a selected printer cannot reproduce page-edge content; no universal safe-area constant.

### Later or explicitly excluded from beta

- Direct Source Data editing, source schema changes, joined-field editing, record insertion/deletion, or database Save Edits.
- Arbitrary Python/Arcade/SQL/VBA-like field calculations or user scripts.
- General joins/relates, source exports, or table data-management workflows.
- A durable ArcGIS-like highlight subset in addition to focus, hover, and selection unless user research proves it necessary.
- Word mirror margins, facing pages, book fold, automatic gutter placement, odd/even sections, continuous sections, and Link to Previous inheritance.
- Generic word-processor widow/orphan, Keep with next, and paragraph-level page-break controls.
- Any assertion that ArcGIS uses a particular virtualization algorithm or that Word supplies draggable ruler guides or a fixed printable-safe margin.

## Acceptance seams for implementation planning

The following black-box seams make the recommended behavior observable without coupling tests to DOM structure:

- Selecting one plotted record updates `selectedRecordIds`, the corresponding table row, and Inspector identity; selecting the table row produces the same result. No duplicate record is created.
- Hovering a plotted point exposes exact displayed value/units/record/series and, when overridden, the source-original value; leaving clears hover without dirty state or history.
- Focus movement never changes a multi-selection unless the selection shortcut is invoked.
- Editing a source-original cell is unavailable with a reason; editing its eligible displayed cell creates a Presentation Override, preserves provenance, and supports one-step undo/redo.
- Invalid presentation input cannot commit, survives long enough to correct, and produces an accessible field message; changing record with a dirty draft follows the declared commit/cancel policy.
- Sort/filter/find can unmount rows without losing selection identity; clearing the state restores the same selected identities when still present in the dataset.
- Bulk Set previews target identity and counts, skips ineligible cells explicitly, produces one history entry, and never changes the Source Snapshot digest.
- Resizing a Page Region by drag and entering the same exact dimension resolve to the same canonical geometry and history command.
- Page-size, margin, or region changes deterministically rebuild pages and Template Variant assignments; undo restores the prior resolved page identities/ranges according to the page-plan contract.
- Guides and grids do not appear in the PDF. Printer-safe warnings depend on the selected device profile and do not change the portable Log Template.

## Evidence gaps that remain

- ArcGIS Pro's UI virtualization, cache, overscan, and numeric performance limits are undocumented in the reviewed sources. RSrender needs its own corpus and budgets.
- ArcGIS documents ToolTips with record variables and values but not an Inspector that remains populated merely from hover. RSrender should keep hover transient and make click/keyboard activation the stable Inspector target.
- The official sources do not resolve how ArcGIS arbitrates an invalid in-cell draft when a cross-view selection arrives. RSrender must define and test this explicitly.
- Current Microsoft Support did not yield a general Word custom-paper-size walkthrough; Microsoft Learn establishes the PageSetup size semantics.
- Word does not provide official evidence for Publisher-style draggable ruler guides or a universal nonprinting-region overlay. Those must remain RSrender-specific behavior and printer-qualified Diagnostics.
