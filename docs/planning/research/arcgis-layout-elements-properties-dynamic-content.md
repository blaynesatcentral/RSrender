# ArcGIS Pro Layout elements, properties, and dynamic content

**Wayfinder ticket:** #4  
**Research date:** 2026-08-13  
**Reference product:** ArcGIS Pro 3.6 documentation (the current `latest` help resolved to 3.6 during this research)  
**Status:** Evidence synthesis; no ArcGIS code, assets, branding, or project files were inspected or copied

## Scope and evidence method

This note decomposes ArcGIS Pro Layout behavior for general graphic elements, text, pictures, styling, property editing, dynamic content, invalid states, persistence, and accessibility. It intentionally does not attempt to reproduce ArcGIS Pro's visual identity.

The evidence base is first-party Esri documentation and the public ArcGIS Pro SDK reference. Most sources are task-oriented help pages that document observable application workflows and visible states. No licensed ArcGIS Pro installation was available for an independent hands-on pass, so any behavior not explicitly covered by those sources is marked **Unverified**, not guessed.

Evidence markers used below:

- **Documented** — explicitly described by a cited Esri source.
- **Inference** — a clean-room conclusion derived from one or more documented behaviors.
- **Unverified** — the reviewed sources do not settle the behavior; it remains a research or prototype question.

The “Reuse class” column distinguishes broadly useful layout-designer behavior from GIS-specific behavior:

- **Core** — broadly reusable in RSrender.
- **Adapt** — useful interaction or data pattern, but RSrender needs its own boring-log semantics.
- **GIS-only** — depends on maps, spatial layers, map series, or Esri-specific authoring concepts and should not be copied as a product feature.

## Findings that constrain RSrender

1. ArcGIS Pro uses a common element shell with specialized content. Elements share naming, visibility, locking, placement, border/background/shadow, Contents representation, and drawing order; type-specific panes add content and symbol properties. This supports an RSrender base-element contract with type-specific property schemas rather than unrelated widgets. [Esri: Work with layout elements](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/work-with-layout-elements.htm)
2. Text container geometry is behavioral, not cosmetic. Rectangle and polygon text preserve font size and wrap, straight text changes font size when resized, and curved text neither wraps nor accepts line breaks. Rectangle text alone exposes explicit overflow fitting strategies. RSrender should therefore persist a text-flow/container kind and overflow policy, not infer behavior from shape. [Esri: Add graphics and text](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/add-and-modify-graphics-and-text.htm), [Esri: Edit text](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/text.htm)
3. ArcGIS dynamic text is live content composed from static text plus structured tags. A gallery and tag-oriented editor provide a guided path, while a raw text/tag view provides an advanced path. This is a strong precedent for RSrender’s field browser plus typed binding editor; the tag syntax itself is Esri-specific and should not be copied. [Esri: Add and modify dynamic text](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/add-dynamic-text.htm)
4. ArcGIS styles are reusable presets, not live inheritance. Applying a style copies it; later changes do not flow in either direction. RSrender’s decided **Named Style** behavior should deliberately differ: keep a stable style reference, resolve inherited values, record local overrides, and provide “reset to style.” [Esri: Styles](https://pro.arcgis.com/en/pro-app/3.6/help/projects/styles.htm), [Esri: Modify symbols](https://pro.arcgis.com/en/pro-app/3.6/help/mapping/layer-properties/modify-symbols.htm)
5. ArcGIS exposes overflow but does not provide the non-silent, export-gating diagnostic contract RSrender requires. Rectangle text with no fitting strategy hides excess text and shows an overflow symbol; auto-width or auto-height can move content off-page. RSrender must retain explicit overflow policies and Diagnostics rather than treating ArcGIS behavior as sufficient. [Esri: Edit text](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/text.htm)
6. ArcGIS accessibility demonstrates that element metadata and order matter outside the visual canvas: tagged PDF reading order follows layout drawing order, text and tables are tagged automatically, and selected graphic element types accept alt text. RSrender should keep an explicit semantic/accessibility representation and should not assume visual z-order is always the correct reading order. [Esri: Export to PDF](https://pro.arcgis.com/en/pro-app/3.6/help/sharing/overview/pdf-export.htm)

## Atomic capability matrix: element taxonomy and creation

| ID | Atomic capability and documented behavior | Reuse class | Clean-room implication for RSrender |
|---|---|---|---|
| E01 | **Common element identity.** Every inserted layout item appears as an element in Contents; common operations include selection, drawing order, visibility, locking, and property editing. **Documented.** [Work with layout elements](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/work-with-layout-elements.htm) | Core | Give every general or semantic element a stable ID, user-facing name, parent, z-order, local visibility, local lock state, and typed property schema. |
| E02 | **Insertion surface.** Graphics and text are chosen from a gallery on the Insert tab. After insertion the default is to return to selection mode; “Keep last tool active” allows repeated creation. **Documented.** [Add graphics and text](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/add-and-modify-graphics-and-text.htm) | Core | Provide one discoverable insert surface, one-shot tools by default, and an explicit repeat-placement mode. Do not reproduce Esri gallery styling or iconography. |
| E03 | **Area primitives.** Rectangle, rounded rectangle, polygon, circle, ellipse, lasso/freehand area, triangle, right triangle, half-circle, cross, X, and cloud are separate gallery choices. Rounded-corner amount is editable in Placement. **Documented.** [Add graphics and text](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/add-and-modify-graphics-and-text.htm) | Core/defer by need | MVP already calls for rectangle and ellipse. Keep the geometry model extensible to other closed paths; do not make the full Esri primitive list an MVP parity gate. |
| E04 | **Line primitives.** Straight-segment line, Bézier curved line, freehand line, and three-point arc are distinct tools. **Documented.** [Add graphics and text](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/add-and-modify-graphics-and-text.htm) | Core/defer by need | MVP needs straight lines and polylines. Preserve a path/segment model so curves can be added without changing element identity. |
| E05 | **Arrow variants.** Straight/curved, single/double arrows are line graphics whose line symbols include endpoint marker arrowheads. **Documented.** [Add graphics and text](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/add-and-modify-graphics-and-text.htm) | Core/defer | Model arrowheads as start/end line decorations, not separate baked images. |
| E06 | **Point graphic.** A point is a graphic carrying a point symbol. **Documented.** [Add graphics and text](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/add-and-modify-graphics-and-text.htm) | Adapt | A generic symbol/marker element can support sample symbols and groundwater markers, but boring-log semantics must remain typed rather than flattened into arbitrary points. |
| E07 | **Rectangle and polygon text.** These preserve authored font size and wrap within the drawn area. **Documented.** [Add graphics and text](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/add-and-modify-graphics-and-text.htm) | Core | Use bounded flow text for most labels and dynamic fields; measure live against exact bounds. |
| E08 | **Straight text.** It honors explicit line breaks, does not wrap, and resizing the element changes font size. **Documented.** [Add graphics and text](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/add-and-modify-graphics-and-text.htm) | Core/defer | If supported, label this behavior clearly as scale-to-box text. It must not be the silent default for data-bound labels. |
| E09 | **Curved text.** It follows a curved line, preserves font size, and supports neither wrapping nor line breaks. **Documented.** [Add graphics and text](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/add-and-modify-graphics-and-text.htm) | Defer | Not needed for professional boring logs in MVP; retaining path-text as a future type is enough. |
| E10 | **Circle and ellipse text.** These preserve font size and wrap inside their geometry. **Documented.** [Add graphics and text](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/add-and-modify-graphics-and-text.htm) | Defer | Do not conflate text frames with their decorative border; a future shaped-flow implementation can be separate from rectangle flow text. |
| E11 | **Picture insertion.** Local/network files and URLs can be inserted. Clicking places at original size; dragging defines a box. Supported inputs include BMP, EMF, GIF, JPEG, PNG, SVG, TIFF, and WebP, with animation limitations. **Documented.** [Add pictures](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/add-pictures.htm) | Core, with narrower policy | RSrender’s decided MVP set is PNG/JPEG/SVG and embedded-only. Reuse click-at-natural-size and drag-to-frame behavior; reject remote hot links and unneeded formats initially. |
| E12 | **Static picture replacement.** A selected picture can be replaced from the Element pane without recreating its layout element. **Documented.** [Add pictures](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/add-pictures.htm) | Core | Keep placement, crop/fit settings, identity, accessibility metadata, and z-order when replacing the embedded image asset. |
| E13 | **Dynamic picture.** In a spatial map series, an attachment or field/expression supplies a picture per page; an empty field draws no picture. **Documented.** [Add pictures](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/add-pictures.htm) | Adapt/GIS-only source | Adapt the typed “image binding” idea to Render Dataset fields or embedded hatch assets. Do not carry over map-series/index-layer concepts or URL-triggered loading. |
| E14 | **Dynamic versus static element categories.** Map frames, extent indicators, grids, north arrows, scale bars, legends, chart frames, table frames, pictures, graphics, text, and dynamic text share the Layout element surface; dynamic elements react to data or map extent. **Documented.** [Work with layout elements](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/work-with-layout-elements.htm) | Adapt | RSrender needs general elements plus semantic Page Regions, Log Columns, Data Tracks, and Data Layers. Map frames and cartographic surrounds are GIS-only. |
| E15 | **Semantic frames.** Chart and table frames are source-backed layout elements with element-level borders/backgrounds/shadows and source-specific property panes. **Documented.** [Chart frames](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/charts.htm), [Table frame fields](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/add-and-modify-table-frame-fields.htm) | Adapt | Data Track and Log Column must be semantic containers with source-aware child properties, not merely groups of primitive graphics. |
| E16 | **Groups.** Grouping retains relative child positions while the group is resized or rotated; group visibility affects all members, and ungrouping preserves the elements. **Documented.** [Work with layout elements](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/work-with-layout-elements.htm) | Core | Preserve child-local properties and ancestry. RSrender has separately decided inherited Effective Visibility and Effective Lock State. |
| E17 | **Convert dynamic to static graphics.** Conversion gives direct control over generated parts but removes dynamic behavior; converting dynamic text replaces the tag with its current displayed value. **Documented.** [Convert grids to graphics](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/grid-convert-to-graphics.htm), [Add and modify dynamic text](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/add-dynamic-text.htm) | Adapt/defer | If RSrender ever offers “detach binding,” make the irreversible semantic loss explicit and undoable. Do not use conversion as the normal editing route for Log Columns or Data Tracks. |

## Atomic capability matrix: editing and property workflow

| ID | Atomic capability and documented behavior | Reuse class | Clean-room implication for RSrender |
|---|---|---|---|
| W01 | **Canvas or tree selection.** An element may be selected on the layout or in Contents before editing. **Documented.** [Work with layout elements](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/work-with-layout-elements.htm) | Core | Canvas and Contents must be synchronized views of one selection model. |
| W02 | **Contextual editing tab.** Selecting one element shows a type-named contextual ribbon tab; selecting multiple elements shows an Element tab containing common properties. **Documented.** [Work with layout elements](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/work-with-layout-elements.htm) | Core | Use selection-sensitive commands/properties without copying the ribbon. Properties should expose the common editable intersection for multi-selection. |
| W03 | **Element pane completeness.** The contextual tab exposes common/high-frequency settings; the Element pane contains every property for the element. It stays open and follows the currently selected Contents item. **Documented.** [Work with layout elements](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/work-with-layout-elements.htm) | Core | Properties is the authoritative granular editor and must update with selection. Canvas controls are accelerators, not the only path to a property. |
| W04 | **Multi-edit eligibility.** Multiple elements may be selected, but only properties common to all are available. **Documented.** The reviewed source does not specify how mixed values are visually represented. [Work with layout elements](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/work-with-layout-elements.htm) | Core | Implement the already-decided mixed-value state explicitly. Do not infer ArcGIS’s precise mixed-value visuals. |
| W05 | **Common Options.** Name, visibility, and lock live on Options; names must be unique in ArcGIS Pro. Type-specific options may be added. **Documented.** [Work with layout elements](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/work-with-layout-elements.htm) | Core, with deliberate difference | RSrender requires stable unique IDs; sibling display names only need to be distinguishable, not globally unique. |
| W06 | **Locked editing.** Locked elements cannot be manually selected or modified on the canvas, but can be selected in Contents and edited in the Element pane. **Documented.** [Work with layout elements](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/work-with-layout-elements.htm) | Core | Matches RSrender’s decided inspectable-lock behavior. Enforce lock at command validation, not only hit-testing. |
| W07 | **Common Display parts.** Border, background, and shadow are separate selectable parts. Borders/backgrounds have symbols, rounding, and x/y gaps; shadows have a symbol and offset. **Documented.** [Work with layout elements](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/work-with-layout-elements.htm) | Core | Model border, fill/background, and shadow as optional structured appearance parts. Avoid creating invisible child elements in Contents unless independently meaningful. |
| W08 | **Common Placement.** Placement includes x/y, width/height, anchor, aspect-ratio lock, and rotation; element coordinates use layout units. **Documented.** [Work with layout elements](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/work-with-layout-elements.htm) | Core | Aligns with physical units and the nine-point Position Anchor. Keep layout geometry independent of screen pixels. |
| W09 | **Multipart limitation.** Size/position commands are unavailable when editing only a multipart subpart such as a picture border. **Documented.** [Work with layout elements](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/work-with-layout-elements.htm) | Core | Property applicability should be typed and explain why a command is disabled. Do not partially apply an invalid transform. |
| W10 | **Inline text edit.** Double-click enters inline editing. Selected spans can be formatted; click outside, Ctrl+Enter, or F2 commits, while Esc cancels. **Documented.** [Edit text](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/text.htm) | Core | Preserve this clear transaction boundary and preview overflow continuously while editing. |
| W11 | **Inline rich-text commands.** Inline editing supports font changes, bold, bullets/sub-bullets, hyperlink creation, underline, case changes, superscript, and subscript through visible controls and shortcuts. **Documented.** [Edit text](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/text.htm) | Core/defer by requirement | MVP needs bounded span-level rich text, not the entire command set. Hyperlinks are not a boring-log priority and raise export/security questions. |
| W12 | **Spell-check feedback.** Misspellings receive wavy red underlines on canvas and in the pane; a project-wide pane lists them and can zoom to affected elements. Acronyms/all-caps are ignored. **Documented.** [Edit text](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/text.htm) | Core/defer | The “diagnostic plus locate” pattern is highly reusable. Spell-check can follow core overflow/data Diagnostics if schedule requires. |
| W13 | **Vertex editing mode.** Lines/shapes expose move/add/delete/continue/finish/cancel operations; multiple vertices can be lasso-selected; segments can be changed among straight, circular arc, and Bézier; line direction can be reversed. **Documented.** [Modify graphics and text](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/modify-graphics-and-text.htm) | Core/defer | MVP polylines need deterministic vertex editing; arc/Bézier conversion can be deferred. Finish and cancel must form one undoable edit transaction. |
| W14 | **Discrete transforms.** Rotate left/right 90 degrees and horizontal/vertical flip are commands; rotate increments the existing angle and flip preserves x/y. **Documented.** [Modify graphics and text](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/modify-graphics-and-text.htm) | Core | Add exact transform commands alongside handles and numeric entry where they are semantically valid. |
| W15 | **Boolean shapes.** Union, intersect, remove overlap, and subtract combine polygon graphics; output takes the first selected graphic’s symbology. Non-overlap can produce unexpected results. **Documented.** [Modify graphics and text](https://pro.arcgis.com/en/pro-app/3.6/help/layouts/modify-graphics-and-text.htm) | Defer | Full illustration tooling is out of MVP. If added later, preview results and validate geometry instead of copying first-selected semantics without review. |
| W16 | **Apply versus live apply.** Complex symbol changes can be staged and applied as one undoable action; an Auto Apply toggle refreshes after each edit and may hurt performance. **Documented.** [Modify symbols](https://pro.arcgis.com/en/pro-app/3.6/help/mapping/layer-properties/modify-symbols.htm) | Core | Matches RSrender’s decided live preview plus single commit. Performance-heavy properties need cancellation/debounce and a clear pending/committed state. |
| W17 | **Default creation properties.** Application options set default font and point/line/polygon symbols for newly created elements; changing a default applies to future creations. **Documented.** [Set default properties](https://pro.arcgis.com/en/pro-app/3.6/help/mapping/layer-properties/set-the-default-properties-for-graphic-elements.htm) | Core | Use template-scoped creation defaults, distinct from Named Styles and existing element values. Application-wide defaults should not silently alter a Log Template. |

## Atomic capability matrix: text flow, overflow, and dynamic content

| ID | Atomic capability and documented behavior | Reuse class | Clean-room implication for RSrender |
|---|---|---|---|
| D01 | **Live dynamic evaluation.** Dynamic text displays a current project/layout/map/table-derived value and updates when the property changes. ## Clean-room product requirements derived from the benchmark

The following are **inferences/recommendations**, not claims about Esri implementation:

1. **Separate five concerns in the element model:** element identity/state, geometry/placement, appearance, content, and binding/evaluation. A Log Column or Data Track can then reuse common layout behavior without being flattened into generic shapes.
2. **Make Properties schema-driven.** Every element type declares readable/editable properties, applicability to multi-selection, units, validation, preview cost, and whether a change belongs to the Log Template or Log Project.
3. **Keep canvas and pane editing transactionally identical.** Inline changes, handle transforms, property edits, reordering, and future MCP commands must invoke the same typed command boundary and produce the same validation and undo record.
4. **Use structured rich text.** Persist paragraphs/spans and binding tokens; do not persist arbitrary HTML/CSS or an Esri-style tag language. Formatting properties must be deterministic in both canvas and PDF backends.
5. **Make dynamic content continuously observable.** A selected bound element shows source field, evaluated value, formatting, missing-value policy, last evaluation state, and any Presentation Override. Canvas output updates after relevant local changes and after accepted Refresh.
6. **Use explicit non-valid states.** At minimum: valid, blank-by-policy, missing, unsupported, type-invalid, source-unavailable, stale, overflowed, overridden, refresh-conflicted, and suppressed. Each state must have a non-color-only cue and a navigable Diagnostic where applicable.
7. **Treat overflow as data.** Text measurement returns fitted bounds, line count, clipped range, effective font size, and overflow status. No renderer/backend may silently discard these results.
8. **Keep Named Style inheritance live and inspectable.** Properties display inherited value, style source, and local override. Updating a Named Style previews affected elements and is undoable; “reset to style” clears only the chosen override.
9. **Keep embedded assets authoritative.** Static pictures and hatches render from package assets. Original paths/URLs are provenance only and must not trigger I/O when a file is opened.
10. **Design accessibility into the model.** Element name, semantic role, decorative flag, alternative description, logical reading order, and binding/diagnostic state must be queryable outside the canvas. Visual z-order and reading order may default together but should be independently validatable.

## Unresolved evidence gaps and follow-up tests

These gaps should not be silently resolved by implementation agents:

1. **Mixed-value UI semantics:** official help says only common properties are available for multi-selection but does not document the exact indeterminate/mixed-value presentation or partial eligibility behavior. RSrender’s already-decided explicit mixed state remains authoritative.
2. **Broken dynamic bindings:** official help documents empty results and one invalid-statistic error, but not the full UI for deleted sources, malformed tags, inaccessible sources, or stale evaluation. RSrender must specify its own Diagnostic states.
3. **Dynamic evaluation timing:** automatic updates are promised but an F5 fallback is documented. Prototype dependency tracking and live evaluation under large multi-page Render Datasets rather than copying this ambiguity.
4. **Picture fitting surface:** reviewed help settles insertion, replacement, embedding, formats, and dynamic paths but not a complete crop/fit/fill/transparency property contract. The rendering prototype must settle RSrender’s already-required preserve-aspect, crop, fit/fill, transparency, rotation, and SVG behavior.
5. **Font-fallback feedback:** fallback is documented, but the reviewed sources do not establish whether authors receive a missing-glyph/font warning. RSrender requires explicit deterministic font Diagnostics regardless.
6. **Inline rich text plus bindings:** sources show formatted spans and dynamic/static composition but do not settle every editing edge case when selection crosses binding tokens. Prototype binding tokens as atomic selectable units with formatting around, not inside, a token unless the formatter explicitly supports it.
7. **Accessible primitive graphics:** the export documentation does not establish alt-text support for every graphic primitive. RSrender should define element metadata independently and test what its chosen PDF backend can tag.
8. **Style update blast radius:** ArcGIS’s copy-on-apply behavior avoids propagation entirely, while RSrender requires live Named Styles. A prototype/spec must settle affected-element preview, override precedence, undo, and migration.
