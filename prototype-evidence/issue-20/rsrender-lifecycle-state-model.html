    Explicit unresolved choices

    The prototype refuses to let these choices hide inside a framework default.

    Assumptions used only for this prototype

    • Mutating edits pause while the candidate-save pipeline is active.
    • Save As does not bind the document to the proposed target until post-replacement verification succeeds.
    • A recovery candidate opens as a separate untargeted recovered document.
    • An untrusted package is refused; an otherwise trusted future-version package gets metadata-only inspection.
    • A missing library template is non-blocking because the project uses its exact embedded effective template.
    • Application rollback is a restart operation that closes application documents but never touches the durable user-file catalogue.

    Decisions still requiring evidence or policy

    • Which storage classes earn durable-save support and whether any may honestly be described as atomic.
    • Whether editing may continue against a later revision while an immutable save snapshot commits.
    • Recovery interval, retention, size, encryption, and whether recovery can ever satisfy a Close/Quit gate.
    • Exact Close/Quit choice ordering across many dirty documents and active exports.
    • External-change choices beyond Save As, including compare/reload and any intentional overwrite authority.
    • Whether Save As a separate `Log Template` creates a new stable template identity.
    • Whether a missing-template warning ever blocks export under firm policy.
    • Metadata-only affordances for incompatible packages and how untrusted/corrupt distinctions are explained.
    • Update authority, restart deferral, rollback window, and supported reader/file compatibility window.
    • One-renderer tabs, one view per tab, or one window per document.
